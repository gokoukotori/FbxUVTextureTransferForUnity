# FBX UV Texture Transfer

あるアバター用に描かれたテクスチャを、**UV の配置が違う別のアバターでも使えるように変形して貼り付ける** Unity のエディター拡張です。VRChat アバター（`VRCAvatarDescriptor` のあるアバター）が対象です。

元のテクスチャ画像は書き換えません。TexTransTool のレイヤーとして重ねるだけなので、いつでも外したりやり直したりできます（非破壊）。

## できること

| 機能 | こんなときに | 追加するコンポーネント |
| --- | --- | --- |
| **テクスチャ転送** | 服の柄・タトゥー・模様などを、別アバターの対応する部分へ移したい | `FBX UV Texture Transfer Layer` |
| **メイク転送**（β版） | 透過 PNG のメイクを、別アバターの顔に合わせて貼りたい | `FBX UV Makeup Transfer Layer (β版)` |
| **アイ転送**（β版） | 別アバター用の瞳テクスチャを、自分のアバターの目に合わせたい | `FBX UV Eye Texture Transfer Layer` |
| **ボディ転送**（β版） | 透過PNGのタトゥー・ペイント・ボディシールなどを、別アバターの体の同じ位置へ貼りたい | `FBX UV Body Overlay Transfer Layer (β版)` |

β版の機能は、仕様や結果が今後変わる可能性があります。変更履歴は [CHANGELOG.md](CHANGELOG.md) を参照してください。

## 用語

| 用語 | 意味 |
| --- | --- |
| UV島 | テクスチャ上で、メッシュの面がひとまとまりに並んでいる領域です。服の前身頃、片目、顔の肌など、パーツごとに分かれています。 |
| 転送元 / 転送先 | 絵を持ってくる側のアバター / 絵を貼り付ける側のアバターです。 |
| MLIC | TexTransTool の `MultiLayerImageCanvas` です。画像編集ソフトのキャンバスのように、テクスチャへレイヤーを重ねます。 |
| Region | テクスチャ転送で「転送元のこの島を、転送先のこの島へ」と決めた1組です。1つのレイヤーに複数作れます。 |

## 動作環境

- Windows / Direct3D 11
- Unity `2022.3.22f1` 以上
- VRCSDK Avatars `3.10.4` 以上
- TexTransTool `1.1.0-beta.9` 以上
- NDMF `1.14.4` 以上

> TexTransTool の backend は **Unity** に設定してください。WGPU backend では転送処理が呼ばれず、空のレイヤーになります。

## 共通の準備

4つの機能とも、TexTransTool のキャンバス（MLIC）の中にレイヤーとして置きます。

1. アバター（`VRCAvatarDescriptor` のある GameObject）の中に空の GameObject を作り、`TTT MultiLayerImageCanvas` を追加します。
2. MLIC の `Target Texture` に、**貼り付け先のテクスチャ**を1つ指定します。
3. MLIC の直下に空の GameObject を作り、使う機能のコンポーネントを `Add Component > Gokoukotori > FBX UV Texture Transfer` から追加します。
4. Inspector で `転送元 Model / Prefab` に、絵を持ってくる側のアバターの Prefab（または FBX）を指定します。`転送先 Model / Prefab` は、親アバターから自動で入ります。自動で入らないときは手で指定してください。

> - 1つの GameObject に置ける転送コンポーネントは1つです。機能ごとに GameObject を分けてください。
> - コンポーネントを追加すると `TTT ExternalToolAsLayer` も自動で付きます。外さないでください。
> - 転送先のテクスチャが複数あるときは、テクスチャごとに MLIC を作ります。

## テクスチャ転送の使い方

アイテクスチャなどを、UV島単位で別アバターへ移します。

1. [共通の準備](#共通の準備)を済ませ、`FBX UV Texture Transfer Layer` を追加します。
2. `転送元テクスチャ` に、持ってきたい絵が描かれたテクスチャを指定します。
3. `UV領域エディターを開く` を押します。
4. `Regionを追加` を押します。
5. 左（転送元）と右（転送先）のプレビューで、対応する UV島をそれぞれクリックします。クリックした時点で保存されます。
6. 移したいパーツの数だけ、4〜5 を繰り返します。
7. Inspector の `現在の設定を検証` を押し、エラーがないことを確認します。
8. NDMF Preview で見た目を確認してから、アバターをアップロードします。

**うまく合わないとき**

- 絵が裏返ったり逆さまになったりする場合は、エディターの `向き補正` で `左右反転`・`上下反転`・`180度回転` を試してください。
- Region が重なる部分は、一覧の下にある Region が上に描かれます。順番は `上へ`・`下へ` で変えられます。
- 一時的に外したい Region は `有効` のチェックを外します。

<details>
<summary>詳しい仕様</summary>

- 1つのレイヤー内の Region は、すべて同じ `転送元テクスチャ` を使います。別の画像から持ってきたいときは、レイヤーを分けてください。
- 新しい Region には `Region`、`Region 2` のような名前が付きます。名前は前後の空白を除いて扱い、空の名前や、大文字・小文字だけが違う同じ名前は付けられません。
- 転送元テクスチャの透明度はそのまま保ちます。転送先の UV島の中で描かれなかった隙間は周りの色で埋めます。元が完全に透明な部分を、この処理で不透明にすることはありません。
- 転送先の UV島の外側には、境界の色を 4px 延ばします（bleed）。
- 生成した画像には、TexTransTool がレイヤーの Opacity・Blend・Layer Mask・Clipping を適用します。

</details>

## メイク転送の使い方（β版）

メイクだけが描かれた透過 PNG を、目・口などの位置に合わせて別アバターの顔へ貼ります。PSD や、肌ごと描かれた画像からメイクだけを取り出す機能はありません。

1. [共通の準備](#共通の準備)を済ませ、`FBX UV Makeup Transfer Layer (β版)` を追加します。MLIC の `Target Texture` には顔のテクスチャを指定します。
2. メイク用に新しい MLIC を作った場合は、**MLIC 自体の Blend を `Normal`（通常）にします**。既定のままだと、透明な部分で下の肌まで置き換わってしまいます。
3. `メイクの透過PNG` にメイク画像を指定します。対応点を合わせやすくするため、`元の顔画像（編集時の背景・任意）` に元の顔テクスチャを指定しておくと便利です。
4. `メイク転送エディターを開く` を押します。
5. **顔の島を選ぶ：** `1. 顔のUV島を選択` で、左右それぞれ顔の肌の UV島をクリックします。
6. **目・口を合わせる：** `目・口の境界候補を提案` を押し、続けて `選んだ境界で初期配置（既存点を置換）` を押します。目頭・目尻・唇などに28点の対応点が置かれます。
7. **微調整：** `2. 対応点を編集` で、左右の画像の点をドラッグして、目や口の位置が合うように直します。
8. Inspector のエラーを確認し、NDMF Preview とアバターの見た目を確認してからアップロードします。

**うまく合わないとき**

- 境界の提案がずれている場合は、`口（緑）`・`UV左眼（水色）`・`UV右眼（黄）` で正しい穴を選び直してから初期配置します。
- 目や口の穴がない顔では、`手動の目印28点を仮配置（既存点を置換）` で仮の点を置き、すべて手で合わせてください。
- 鼻の位置も合わせたいときは `鼻先の候補を1点追加` を使います。候補が出ない場合は `対応点を追加` で手で置けます。
- 初期配置は既存の対応点を置き換えます。手で調整したあとに押すと、調整がやり直しになります（Undo で戻せます）。
- 別のメイク画像を重ねたいときは、レイヤーを分けます。

<details>
<summary>詳しい仕様</summary>

- 境界の提案は、UV 上の左右・上下の位置から推測する補助機能です。余分な穴がある顔でも、目・口の穴を選べば初期配置できます。提案するだけでは、保存済みの対応点は変わりません。
- 顔の UV島を選び直しても対応点は残ります。位置を確認し直してください。
- 対応点は 3〜128 組で、UV 座標は 0〜1 の範囲である必要があります。点が重なっている、一直線に並んでいる、顔を囲んでいない、どうしても裏返りが残る、といった場合は描画せず理由を表示します。
- `変形の安定化係数`（0〜0.1）を上げると、対応点からの多少のずれを許して変形をなめらかにします。0 では対応点に正確に合わせます。保存済みの対応点は変わりません。
- 初期配置で口の点を作った場合は、顔 UV の口の穴の形に合わせて自動で補正します。補正できないときは通常の変形のままにします。
- Inspector の `基本対応を検査` で、変形の検査結果・口の補正状況・対応点の最大ずれを確認できます。
- メイク画像の透明度はそのまま保ちます。転送元は選んだ顔の三角形の中だけを読み、出力も転送先の顔の UV島の中だけに描きます。外側への bleed は付けません。
- 鼻先の候補は、モデルの正面が +Z、上が +Y である前提で、目と口を基準に顔の中央で最も前に出た頂点を探します。鼻の点は変形全体に影響するため、追加後は目・口・頬と表情の変化も確認してください。目・口の初期配置や手動の仮配置をやり直すと、鼻の点も置き換わります。
- 検査で問題がなくても、形や色の自然さまでは保証できません。表情を変えたときや斜めからの見え方も確認してください。

</details>

## アイ転送の使い方（β版）

別アバター用の瞳テクスチャを、自分のアバターの目の形に合わせて貼ります。瞳孔（黒目の中心）が別パーツになっている目にも、画像に描き込まれている目にも使えます。

1. [共通の準備](#共通の準備)を済ませ、`FBX UV Eye Texture Transfer Layer` を追加します。MLIC の `Target Texture` には目のテクスチャを指定します。
2. Inspector の `転送元テクスチャ` に、持ってきたい瞳テクスチャを指定します。
3. `アイ転送エディターを開く` → `目を追加` で片目を登録します。左右の目が別の UV島なら、もう片方も `目を追加` で登録します。
4. `瞳孔の構成` を選びます。
   - **別パーツあり**（既定）：転送元の瞳孔が別パーツのとき。`転送元：虹彩`・`転送元：瞳孔`・`転送先：目` の3つで、同じ側の目の島をクリックします。
   - **別パーツなし（画像一体型）**：瞳孔が画像に描かれているとき、または瞳孔がないとき。`転送元：虹彩` と `転送先：目` の2つを選びます。
5. `自動計測を確認` で、瞳孔の位置や大きさが自動でどう配置されるかを確認します。ずれていれば、瞳孔の位置・大きさ・縦横比を補正します。
6. `設定を検証` で問題がないことを確認し、TexTransTool のプレビューでアバター上の見え方を確認します。

**うまく合わないとき**

- 模様の伸び方が気になる場合は、`補正方式` を `従来型`（既定）と `トポロジー型` で切り替えて比べてください。
- 細かい位置は `手補正` タブで直せます。`手補正を有効にする` を入れ、`補正ピンを追加` で結果画像の虹彩をクリックし、ピンをドラッグすると周りの絵が動きます。動かしたくない場所には `固定ピンを追加` で固定ピンを置きます。
- `押している間は手補正前` を押している間は、手補正前の結果を表示します。
- 小さな島は `選択中の島を拡大` やマウスホイールで拡大すると選びやすくなります。

<details>
<summary>詳しい仕様</summary>

**配置の仕組み**

- 虹彩は目の外周に合わせて変形します。瞳孔は、転送元の縦横比と、虹彩に対する面積の比率を保って配置します。転送先の目の縦横比が違うときは、幅と高さの比率を両方そのまま保つことはできません。
- 瞳孔の位置補正は、転送先の目の幅・高さを 1 とした値です。+X がアバターの左、+Y が上です。縦横比倍率は、面積を保ったまま幅÷高さを変えます。倍率 1・位置補正 0 が自動配置です。
- 瞳孔の自動計測は転写のたびに行うので、`自動計測を確認` を押さなくても転写できます。
- 画像一体型では、別パーツの瞳孔の選択と、位置・大きさの補正は使いません。画像から瞳孔を見つける機能ではなく、画像の瞳孔がメッシュの中心付近に描かれている前提です。構成を切り替えても、以前の瞳孔の選択と補正値は残ります。

**トポロジー型**

- 外周を保ったまま、立体の三角形の形を手がかりに内部の対応を計算します。穴のない虹彩にも使えます。
- 虹彩に瞳孔用の穴が1つあるときは、穴の縁を補正後の瞳孔の外周に合わせます。
- 画像一体型では、面の辺が一点に集まる頂点を瞳孔の中心として合わせます。扇状のメッシュの中心や、8本以上の辺が集まる頂点が対象です。見つからない場合は中心を固定せずに変形します。画像一体型でトポロジー型を使うには、穴のない虹彩が必要です。
- 虹彩に穴が複数ある、瞳孔が目からはみ出す、面が裏返る・重なる、計算が収束しない、といった場合は理由を表示して止まります。自動で従来型に切り替えることはありません。

**手補正**

- ピンは目ごとに最大 32 個です。`影響範囲` は、目の幅・高さを 1 とした半径です。外周・虹彩の穴・別パーツの瞳孔の手前までに制限されます。
- ドラッグ中は仮の結果を表示し、マウスを離すと確定します。1回の確定は1回の Undo で戻せます。Esc、フォーカスの移動、目やタブの切り替えでドラッグを取り消します。
- 絵が裏返る位置へは動かせません。`未反映` と理由を表示し、最後に描けた結果を表示したままにします。安全側に判定するため、実際には裏返らない位置でも拒否することがあります。移動量を減らすか、影響範囲を広げてください。
- ピンごとの移動の取り消し・削除と、`手補正をすべてリセット` が使えます。手補正を無効にしてもピンは残ります。
- 領域・補正方式・瞳孔の構成を変えると、以前のピンは自動で引き継がず、リセットか無効化を求めます。
- 手補正のプレビューは編集用に最大 1024px で表示し、他のレイヤーやシェーダーの効果は含みません。最終的な解像度は Canvas の設定に従います。

**前提と制限**

- モデルの正面が +Z、上が +Y の配置を前提にします。
- 計測には Renderer の `sharedMesh` の標準の形を使います。BlendShape、ポーズ、シェーダーによる色・UV の変化やハイライトは計測に含みません。輪郭はメッシュから取り、画像の透明度からは推定しません。
- 中心から放射状に外周をたどれる目に対応します。別パーツの瞳孔と転送先の目は、それぞれ穴のない形である必要があります。閉じた輪郭が取れない領域は、理由を表示して転写しません。トポロジー型では、正面から見て面が重なっている領域も使えません。
- 左右の目が同じ UV を共有している場合は、その島をそのまま選べます。離れた領域は内部で分けて補正します。転送元と転送先で領域の数が違っても、位置の近いもの同士を対応させます。
- 出力は選んだ転送先の UV 内だけに描き、外側への bleed は付けません。元画像の透明度は保ちます。
- アバター全体から虹彩や瞳孔を自動で見つける機能ではありません。

</details>

## ボディ転送の使い方（β版）

透過PNGで描いた絵（タトゥー・ペイント・ボディシールなど）を、転送元アバターの体の上の位置のまま、別アバターの体へ貼ります。UV の配置が違っても、体の形（3D）を手がかりに同じ位置へ対応させます。

1. [共通の準備](#共通の準備)を済ませ、`FBX UV Body Overlay Transfer Layer (β版)` を追加します。MLIC の `Target Texture` には、転送先の**ボディのテクスチャ**を指定します。
2. 転送先の Model / Prefab と、転送元の Model / Prefab を指定します。どちらも Humanoid のアバターである必要があります。
3. `オーバーレイ画像` に、貼りたい透過PNGを指定します。この画像は、転送元ボディのテクスチャと同じ UV で描かれたものとして扱います。
4. `転送元ボディテクスチャ` を確認します。転送元で「body」を含む名前のマテリアルから自動で選びます。違うときは `自動で選ぶ` を押すか、手で指定してください。
5. Inspector の `診断` を押します。転送元が見つかった割合と警告が表示されます。
6. 位置がずれている部分があれば、`ボディ転送エディターを開く` で補正ピンを置いて直します（`補正を有効にする` を入れると反映されます）。
7. `現在の設定を検証` で問題がないことを確認し、NDMF Preview で見た目を確認してからアップロードします。

`乳首を目印に合わせる`（初期値はオン）は、胸で辺が扇状に集まる点（乳首）を左右の目印として、転送元と転送先の位置を合わせます。素体の違うアバターでも、乳輪などが転送先の乳首に合います。使えなかったとき（乳首が見つからない、左右が対称でない、ずれが大きすぎる、など）は、Inspector の `診断` に理由が出ます。ボディ転送エディターでは、目印に使った転送先の乳首の位置に水色の輪が出ます（`ピン` の表示切り替えに従います）。すでに補正ピンで胸のまわりを直しているレイヤーは、見え方が変わることがあります。必要なら `乳首を目印に合わせる` のチェックを外してください。

**うまく合わないとき**

- Inspector の `診断` に、転送元が見つかった割合（98% 未満だと警告）と、割合の低い部位の名前が出ます。
- 補正はエディターで行います。`補正ピンを追加` で、結果画像の動かしたい場所をクリックしてピンを置き、ドラッグすると周りの絵が動きます。動かしたくない場所には `固定ピンを追加` で固定ピンを置きます。
- `押している間は補正前` を押している間は、補正前の結果を表示します。`診断表示` で、見つからなかった場所を確認できます。
- ピンの操作は、アイ転送の手補正と同じです。ドラッグ中は仮の結果を表示し、マウスを離すと確定します（1回の確定は1回の Undo で戻せます）。絵が裏返る位置など、反映できない変更は `未反映` と理由を表示して保存しません。ドラッグ中は最後に描けた結果を表示したままにします。ピンごとの取り消し・削除と、`すべてリセット` が使えます。

**注意**

- 服の下の面が削除された prefab（体が服の下で欠けているもの）は、その部分に転送されません。着せ替え用の prefab（服の下の面が残っているもの）を指定してください。
- 形状は BlendShape をすべて 0 にして求めます。服の下を隠すための BlendShape（体を縮めるもの）は無視されます。
- 指先・足先は精度が落ちます。必要なら補正ピンで直してください。
- 他のメッシュと共有しているテクスチャのうち、転送元のボディに無い部分（例：顔がボディのテクスチャを共有していて、転送元のボディに頭が無い場合の頭）は、透明のままになります。`診断` では、割合の低い部位として表示されます。
- Humanoid のアバターが必須です。Hips・Spine・Head と、左右の UpperArm・LowerArm・Hand・UpperLeg・LowerLeg・Foot が両方のアバターに必要です。
- ピンの裏返り判定は安全側です。実際には裏返らない位置でも、`未反映` として拒否することがあります。移動量を減らすか、影響範囲を広げてください。

<details>
<summary>詳しい仕様</summary>

- 対応づけの解像度は、Canvas の大きさ（幅・高さの大きい方、最大 2048）です。4096 の Canvas では、2048 の対応を補間して使うため、細い線はぼける可能性があります。
- 対応は、転送元と転送先の骨格を合わせてから、表面を近づけて求めます。結果は、同じアバターの組み合わせで使うレイヤーどうしで共有します。オーバーレイ画像とピンを変えても、対応は計算し直しません。
- 対応の結果は、アバターの組み合わせ・解像度・`乳首を目印に合わせる` ごとに1件、合わせて2件までメモリに保持します。ボディ転送エディターとプレビュー（TexTransTool・NDMF）は最大 1024、`診断`・`現在の設定を検証`・ビルドは Canvas の解像度（最大 2048）で計算します。そのため Canvas が 1024 より大きいと1組でも2件を使い、編集後の最初の `診断`・検証・ビルドでは計算し直すことがあります（数秒かかります）。同時に使う組み合わせが3組以上（Canvas が 1024 より大きいときは2組以上）あると、切り替えのたびに計算し直します。
- 転送先の UV を左右で共有している部分は、片側だけを使い、警告を表示します。
- 転送先の UV島の外側には、境界の色を 4px 延ばします（bleed）。元画像の透明度は保ちます。
- ピンは最大 32 個で、既定の影響範囲は 5cm です。固定ピンは、周りが動いてもその場所を動かさないために使います。

</details>

## エディターの共通操作

エディターは4つあります（UV Region Editor・メイク転送エディター・アイ転送エディター・ボディ転送エディター）。ボディ転送エディターでは UV島や Region を選ばないため、最初の2つの項目と `Region / 目の管理` は、ほかの3つのエディターの操作です。残りの項目は4つとも同じです。

- **選ぶと即保存（ボディ転送エディター以外）：** プレビューの UV島をクリックするか、`UV島` のポップアップで選ぶと、その場で保存されます。保存ボタンはありません。
- **候補の切り替えは保存されない（ボディ転送エディター以外）：** `メッシュ / サブメッシュ` や UV チャンネルを切り替えるのは表示の変更だけです。島をクリックするまで保存済みの設定は変わりません。候補が1つだけのときはそのメッシュを自動で表示しますが、島は自動では保存しません。
- **拡大・移動：** マウスホイールで拡大、中ボタンのドラッグで移動します。`全体` で全体表示に戻り、`選択中の島を拡大` で選択中の島に寄ります（ボディ転送エディターでは、選択中のピンがある島）。
- **Undo / Redo：** すべての変更を Ctrl+Z / Ctrl+Y で戻せます。
- **レイヤーの切り替え：** 先頭の `編集中` 欄に編集中のレイヤーが表示されます。Hierarchy で別のレイヤーを選ぶと切り替わります。
- **Region / 目の管理（テクスチャ転送・アイ転送）：** テクスチャ転送の Region とアイ転送の目は、同じ並びのボタン（`…を追加`・`この…を削除`・`上へ`・`下へ`）で管理します。削除するときは確認ダイアログが出ます。
- **メニューから開く：** `Tools > Gokoukotori > FBX UV Texture Transfer` から、`UV Region Editor`・`Makeup Transfer Editor`・`Eye Transfer Editor`・`Body Overlay Editor` を開けます。

## 困ったとき

**レイヤーが空になる / 何も描かれない**

- TexTransTool の backend が **Unity** になっているか確認してください（WGPU は非対応です）。
- レイヤーの GameObject が MLIC の直下にあるか確認してください。間に GameObject を挟む場合は、挟んだすべてに `LayerFolder` が必要です。
- `TTT ExternalToolAsLayer` が付いているか、同じ GameObject に転送コンポーネントが2つ以上ないかを確認してください。
- Inspector でエラーの内容を確認してください。テクスチャ転送は `現在の設定を検証`、アイ転送は `設定を検証` を押すと表示されます。メイク転送は Inspector に常に表示されます。

**エディターにメッシュの候補が出ない**

- `転送元 Model / Prefab`・`転送先 Model / Prefab` が指定されているか確認してください。Project 内の Prefab、Model Prefab、Prefab Variant のいずれかのルートを指定します。
- 転送先の候補には、MLIC の `Target Texture` を使っているマテリアルのメッシュだけが出ます。MLIC に指定したテクスチャが合っているか確認してください。

**「メッシュ内容が保存時と異なります」という警告が出る**

アバターの FBX を差し替えたり、再インポートしたりしてメッシュが変わると表示されます。古い選択のまま使うと、違う場所に絵が貼られるおそれがあります。エディターで UV島をクリックして選び直してください。メイク転送では対応点も確認し直してください。

**Model / Prefab を変えたら選択が合わなくなった**

Model / Prefab を変えても、保存済みの選択は自動で別のメッシュに置き換わりません。エディターで候補を選び、UV島をクリックし直してください。

<details>
<summary>メッシュ内容のチェックについて</summary>

UV島を選ぶと、そのメッシュの内容から計算した値（ハッシュ）を一緒に保存します。UV、選んだサブメッシュの三角形、頂点数などから計算しており、FBX ファイル全体のハッシュではありません。メッシュが変わってこの値が合わなくなると、エディターで警告し、検証やビルドでもエラーになります。アイ転送の立体計測は、この値に関係なく現在のメッシュの形を読み直します。

</details>

## 注意事項

- 本パッケージは TexTransTool の Experimental API（`ExternalToolAsLayer`、`IExternalToolCanBehaveAsImageLayerV1`）を使っています。この API は安定版ではないため、今後の TexTransTool の更新で動かなくなる可能性があります。
- 依存パッケージのバージョンに上限は設けていませんが、未確認の新しいバージョンでの動作は保証できません。必要な最小バージョンは [package.json](package.json) にあります。
- Inspector の `Canvasの対象テクスチャ` は確認用の表示です。貼り付け先は親の MLIC で設定します。
