# FBX UV Texture Transfer

FBX UV Texture Transfer は、VRChat アバターのテクスチャを別の UV 配置へ転送し、TexTransTool の `MultiLayerImageCanvas`（MLIC）上で非破壊に適用する Unity エディタ拡張です。`VRCAvatarDescriptor` のあるアバターを対象とします。

| コンポーネント | 用途 | 対応付けの方法 |
| --- | --- | --- |
| `FBX UV Texture Transfer Layer` | UV島単位のテクスチャ転送 | Region Binding ごとに転送元・転送先の UV島を1組選択 |
| `FBX UV Makeup Transfer Layer (β版)` | 透過 PNG のメイクを別アバターの顔へ転送 | 顔の UV島を選択し、目・口などの対応点を調整 |

変更履歴は [CHANGELOG.md](CHANGELOG.md) を参照してください。

## 対応環境

- Unity `2022.3.22f1` 以上
- VRCSDK Avatars `3.10.4` 以上
- TexTransTool `1.1.0-beta.9` 以上
- NDMF `1.14.4` 以上
- Windows / Direct3D 11
- TexTransTool の Unity backend

依存パッケージの最小バージョンは [package.json](package.json) に定義し、上限は設定していません。`0.2.0-beta.3` 更新時点の開発プロジェクトは Unity `2022.3.22f1`、VRCSDK Avatars `3.10.5`、TexTransTool `1.1.0-beta.9`、NDMF `1.14.8` を使用しています。将来バージョンの互換性を個別に保証するものではありません。

## 共通の設定と制約

本パッケージは TexTransTool の Experimental API である `ExternalToolAsLayer` と `IExternalToolCanBehaveAsImageLayerV1` を使用します。この API には `TexTransToolStablePublicAPI` が付与されておらず、将来の TexTransTool 更新で破壊的に変更される可能性があります。依存範囲に上限は設けませんが、未確認の将来バージョンでエラーが発生した場合は互換性を保証しません。

- レイヤーは MLIC の直下、または `LayerFolder` 配下に配置します。MLIC までに中間の GameObject を置く場合、そのすべてに `LayerFolder` が必要です。
- 同じ GameObject に転送コンポーネントを追加すると、`TTT ExternalToolAsLayer` が自動追加されます。通常転送とメイク転送は別の GameObject に配置してください。`ExternalToolAsLayer` が欠けている場合や、同じ GameObject に複数の ExternalTool 実装がある場合は検証エラーになります。
- `転送元 Model / Prefab` と `転送先 Model / Prefab` には、Project 内の通常 Prefab、Model Prefab、または Prefab Variant のメインルートを指定します。転送先が未設定なら親アバターの Prefab から自動設定します。Prefab 接続がなく自動決定できない場合は手動指定してください。既存の指定は上書きしません。
- 転送先のメッシュ・サブメッシュ候補は、親 MLIC の対象テクスチャをマテリアルが参照しているものに限定します。選択した組み合わせが実際のアバター内でも使用されていることを検証します。
- メッシュ・サブメッシュ・UVチャンネルの変更は表示候補の変更です。UV島をクリックして初めて選択がコンポーネントに保存されます。転送先候補が1組だけなら自動表示しますが、UV島は自動選択・保存しません。

Model / Prefab を変更しても、保存済みの領域を別メッシュへ暗黙に置き換えません。選択済みメッシュが候補にない場合は、エディターで候補を選び、UV島をクリックして選択し直してください。無効な設定はビルド時の検証でもエラーになります。

1 個の MLIC が扱える転送先テクスチャは1個です。複数の転送先テクスチャへ出力する場合は、転送先ごとに MLIC とレイヤーを作成してください。Inspector の `Canvasの対象テクスチャ` は確認用で、適用先は親 MLIC で設定します。

転送画像の生成後に、TexTransTool がレイヤーの Opacity、Blend、Layer Mask、Clipping を適用します。

TexTransTool の backend は Unity に設定してください。WGPU backend は非対応で、`ExternalToolAsLayer` の転送処理が呼び出されず空レイヤーになります。

## 通常転送の操作手順

1. `VRCAvatarDescriptor` のある GameObject の配下に空の GameObject を作成し、`TTT MultiLayerImageCanvas` を追加します。
2. MLIC の `Target Texture` に転送先テクスチャを1個指定します。
3. MLIC の直下、またはその `LayerFolder` 配下にレイヤー用 GameObject を作成し、`Add Component > Gokoukotori > FBX UV Texture Transfer > FBX UV Texture Transfer Layer` を追加します。
4. `転送元 Model / Prefab` を指定し、`転送先 Model / Prefab` の自動設定結果を確認します。自動決定できない場合は転送先も指定します。
5. `転送元テクスチャ` にレイヤー内で共有する画像を指定します。
6. Inspector の Region Binding 一覧の `＋` で Region を追加し、名前、有効状態、向き補正、合成順を設定します。合成は一覧の上から順に行います。
7. `UV領域エディターを開く` を押し、`マッピングするRegion` を選びます。左右それぞれのメッシュ・サブメッシュ・UVチャンネルを確認し、対応する UV島をクリックして保存します。Region ごとにこの操作を繰り返します。
8. Inspector の `現在の設定を検証` を押してエラーを解消します。設定変更後は再度検証してください。
9. NDMF Preview で結果を確認してからアバターをビルドします。

UV Region Editor は `Tools > Gokoukotori > FBX UV Texture Transfer > UV Region Editor` からも開けます。Region の追加・削除・並べ替え・向き補正は Inspector で行い、エディターでは UV島の対応付けを行います。

### Region と転送画像

1 個の Region Binding に転送元・転送先の UV島を1組保存します。新規 Region には `Region`、`Region 2` のような一意名が付きます。名前は前後の空白を除去し、大文字・小文字を区別せずに空名と重複名を拒否します。

`向き補正` は `そのまま`、`左右反転`、`上下反転`、`180度回転` から手動指定します。まず既定の `そのまま` で結果を確認し、UV島の向きが異なる Region だけ補正してください。

レイヤー内のすべての Region Binding は、同じ転送元テクスチャを共有します。複数の転送元テクスチャを使う場合は、テクスチャごとにレイヤーを分けてください。

転送元テクスチャの alpha を保持し、透明・半透明の画素も有効な転送元の値として扱います。転送先 UV島内で描画されなかった画素は、描画済みの画素から補完します。元画像の alpha が0の画素を、この補完で不透明化することはありません。転送先 UV島の外側には4pxの bleed（境界色の延長）を生成します。

## メイク転送レイヤー（β版）

メイクだけを含む透過 PNG を、顔の対応点に合わせて別アバターの顔 UV へ転送します。PSD や肌込み画像からのメイク抽出は扱いません。Python や外部サービスは必要ありません。

### 操作手順

1. 転送先アバター配下の MLIC に、転送先の顔テクスチャを指定します。メイクだけの新規 Canvas を重ねる場合は、**MLIC 自体の Blend を `Normal`（通常合成）に設定**します。既定の置換では下地の肌も透過部分で置換されるためです。既存 Canvas を使う場合は、その下地レイヤーと合成構成に合わせてください。
2. MLIC の直下、またはその `LayerFolder` 配下に空の GameObject を作り、`Add Component > Gokoukotori > FBX UV Texture Transfer > FBX UV Makeup Transfer Layer (β版)` を追加します。
3. `転送元 Model / Prefab` を指定し、`転送先 Model / Prefab` の自動設定結果を確認します。`メイクの透過PNG` にメイク画像を指定します。`元の顔画像（編集時の背景・任意）` には、対応点を確認するための顔画像を指定できます。
4. `メイク転送エディターを開く` を押します。`1. 顔のUV島を選択` で、左右それぞれのメッシュ・サブメッシュ・UVチャンネルを確認し、顔の肌の UV島をクリックして保存します。
5. `目・口の境界候補を提案` を押し、画像上の境界番号を確認します。必要なら `口（緑）`、`UV左眼（水色）`、`UV右眼（黄）` の境界を左右それぞれ選び直します。この提案だけでは保存済みの対応点は変更されません。
6. `選んだ境界で初期配置（既存点を置換）` を押して28点を生成します。必要な閉境界がない場合は `手動の目印28点を仮配置（既存点を置換）` を使います。手動の仮配置は自動検出した位置ではないため、両方の画像で各部位へ合わせてください。どちらの操作も既存の対応点を置き換えます。
7. `2. 対応点を編集` で目頭・目尻・唇などが対応するよう点を調整します。一覧で点を選び、左右の画像をクリック・ドラッグするか、UV座標を数値編集します。点の追加・削除と Undo / Redo に対応します。
8. Inspector のエラーを解消し、`基本対応を検査` で変形と口境界の補正状況を確認します。NDMF Preview とアバター表示で仕上がりを確認してからビルドします。

境界候補の提案は UV 上の左右・上下配置に基づく補助機能です。余分な穴がある顔でも、独立した目・口の閉境界を選択して初期配置できます。顔の UV島を選び直しても既存の対応点は保持するため、位置を確認し直してください。異なるメイク PNG はレイヤーを分けて重ねます。

### 変形の安定化係数と検査

`変形の安定化係数` は0〜0.1で設定し、対応位置を正則化する強さを調整します。0は正則化なしで、値を上げると対応点からのずれを許容します。係数によらず同じ三角形補間を使い、保存済みの対応点は変更しません。

目・口の初期配置などで作った口の目印がある場合は、係数によらず、選択した顔 UV の口の閉境界を使って自動補正を試みます。口周辺では保存点より実際の UV境界を優先し、外側は基本の変形につなぎます。境界が取得できない場合や、反転・重なりを避けられない場合は通常の対応点補間を維持します。追加操作は不要で、対応点や設定値は書き換えません。

`基本対応を検査` には、三角形補間の検査結果、口境界の補正状況、対応点の最大ずれを表示します。対応点は3〜128組で、UV座標は0〜1の範囲が必要です。重複・一直線上の配置、顔領域を囲まない配置、解消できない局所反転や重なりがある場合は描画せず理由を表示します。

元 PNG の透明度を保持し、転送元は選択した顔の三角形内だけを参照します。穴や同じ矩形内の別領域の色を除外し、出力も転送先 UV島内に限定します。通常転送と異なり、外側への bleed は生成しません。検査だけでは形状や色の自然さを保証できないため、表情や斜めからの見え方も確認してください。

### 鼻先の対応点

メイク転送エディターの `鼻先の候補を1点追加` で、選択した両方の顔メッシュから鼻先候補を追加できます。既存の対応点・安定化係数は保持します。追加した点は移動・数値編集・削除でき、Undo にも対応します。目・口の初期配置や手動の仮配置で既存点を置き換えると、追加した鼻点も置き換わります。

候補はモデルの正面 +Z・上 +Y を前提に、目と口の境界を基準として顔中央の最も前に出た頂点を探します。候補が得られない顔や向きが異なるモデルでは、`対応点を追加` から手動指定してください。鼻先とメイクのハイライト中心は必ずしも一致しません。鼻点は変形全体へ影響するため、追加後は目・口・頬と表情変化を確認し、必要に応じて調整してください。保存済みレイヤーには自動追加しません。

## UV島の選択とメッシュ内容ハッシュ

通常転送・メイク転送とも、UV島の選択時にメッシュ内容ハッシュを保存します。ハッシュは UV、選択サブメッシュの三角形インデックス、頂点数などから計算します。FBX ファイル全体のハッシュではありません。

メッシュの差し替えや再インポートなどでこれらの内容が変わった場合、保存済みの UV島の選択は自動追従しません。エディターでメッシュ・サブメッシュ・UVチャンネルを確認し、UV島をクリックして選択し直してください。メイク転送では対応点も再確認します。ハッシュ不一致を無視して以前の選択を適用すると、別の三角形や UV領域へ転送される可能性があります。
